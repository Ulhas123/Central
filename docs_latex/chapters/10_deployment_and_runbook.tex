\section{Deployment Runbook \& Enterprise Cloud Blueprint}
\label{sec:deployment}

\subsection{Local Reproduction Runbook}
To enable immediate, zero-friction verification by the CentrAlign AI technical evaluation panel, CentraOperator can be cloned, tested, and executed locally in minutes without requiring Docker or third-party cloud accounts.

\subsubsection{Prerequisites}
\begin{itemize}
  \item Python 3.10+ (tested on Python 3.12)
  \item Node.js 18+ and npm
\end{itemize}

\subsubsection{Step 1: Dependency Installation}
From the \texttt{centra-operator/} repository root, install dependencies for each microservice:
\begin{lstlisting}[language=bash, caption={Installing Microservice Dependencies}]
# 1. Target Enterprise ERP dependencies
cd services/erp && npm install

# 2. Ingress Gateway & Queue dependencies
cd ../gateway && npm install

# 3. Mission Control React Dashboard dependencies
cd ../dashboard && npm install

# 4. Agent Runtime Python dependencies
cd ../runtime && pip install -r requirements.txt
\end{lstlisting}

\subsubsection{Step 2: Automated Unit Test Suite}
Execute the comprehensive test suite validating isolated primitives:
\begin{lstlisting}[language=bash, caption={Executing Isolated Unit Tests}]
cd ../..
python -m unittest discover tests
\end{lstlisting}
The suite validates five foundational engineering invariants:
\begin{enumerate}
  \item \texttt{test\_idempotency.py}: Concurrent lock rejection and duplicate prevention.
  \item \texttt{test\_graph\_resume.py}: State serialization, HITL pause, and lossless resume.
  \item \texttt{test\_web\_tool.py}: HTML parsing, hidden CSRF extraction, and form models.
  \item \texttt{test\_verifier.py}: False-positive rejection against deceptive UI states.
  \item \texttt{test\_audit\_chain.py}: Mathematical tamper detection upon log alteration.
\end{enumerate}

\subsubsection{Step 3: Automated Benchmark Suite Execution}
Launch the simulated ERP in one terminal window:
\begin{lstlisting}[language=bash]
cd services/erp && node server.js  # Listening on http://localhost:4000
\end{lstlisting}
In a second terminal, execute the automated benchmark evaluation:
\begin{lstlisting}[language=bash]
python eval/run_eval.py
\end{lstlisting}

\subsubsection{Step 4: Launching Full Mission Control Dashboard}
To operate the complete 4-tier interactive environment:
\begin{enumerate}
  \item \textbf{Target System (CentraERP):} \texttt{cd services/erp \&\& node server.js} (Port 4000)
  \item \textbf{Autonomous Runtime:} \texttt{cd services/runtime \&\& python main.py} (Port 8000)
  \item \textbf{Ingress Gateway:} \texttt{cd services/gateway \&\& npm start} (Port 3000)
  \item \textbf{Mission Control Dashboard:} \texttt{cd services/dashboard \&\& npm run dev} (Port 5173)
\end{enumerate}
Open \texttt{http://localhost:5173} in any browser to launch tasks, view real-time state telemetry, inspect audit proofs, and test live human approvals.

\subsubsection{Multi-Tenant Isolation Strategy}
\begin{itemize}[leftmargin=*]
  \item \textbf{Vector Store Partitioning:} All Qdrant collections partition embeddings using mandatory tenant payload filters, preventing cross-organization SOP or episodic memory leakage.
  \item \textbf{Cryptographic Key Isolation:} Each enterprise tenant maintains a dedicated cryptographic key-pair in KMS for signing audit receipts and sealing tamper-evident logs.
  \item \textbf{Network Isolation:} Agent runtime pods operate inside private VPC subnets with egress restricted strictly to authenticated enterprise ERP endpoints via NAT Gateways.
\end{itemize}
