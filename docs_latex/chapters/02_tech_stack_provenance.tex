\subsection{Strategic Technology Omissions and Architectural Justification}
In systems engineering, what is intentionally excluded is often as informative as what is included. CentraOperator deliberately enforces strict architectural constraints:

\subsubsection{1. Omission of Heavy Browser Automation (Playwright / Selenium)}
\begin{itemize}[leftmargin=*]
  \item \textbf{Decision:} The agent interacts with the target ERP at the HTTP protocol layer using Python's standard library (\texttt{urllib.request}, \texttt{http.cookiejar}, \texttt{html.parser}).
  \item \textbf{Justification:} Production browser automation frameworks introduce massive binary dependencies (Chromium/WebKit $\approx 400\text{MB}$), non-deterministic rendering delays, DOM race conditions, and headless memory leaks. For enterprise web portals that rely on standard server-rendered HTML and form submissions, a protocol-level agent operates with zero external dependencies, completes operations in $<100\text{ms}$ (sub-millisecond execution vs multi-second page loads), and isolates web interaction behind a clean tool abstraction (\texttt{web\_open}, \texttt{web\_submit}) that can be swapped for a headless driver in the future without changing a single line of state-graph logic.
\end{itemize}

\subsubsection{2. Omission of In-Container Virtualization (Docker)}
\begin{itemize}[leftmargin=*]
  \item \textbf{Decision:} The prototype executes as native microservices managed via standard process managers or clean scripts.
  \item \textbf{Justification:} Running microservices natively avoids container virtualization overhead, permits immediate step-through debugging in IDE environments, eliminates Docker daemon networking bottlenecks on local machines, and aligns with standard serverless/bare-metal deployment patterns.
\end{itemize}

\subsubsection{3. Omission of External OCR and PDF Parser Packages}
\begin{itemize}[leftmargin=*]
  \item \textbf{Decision:} Ingested vendor communications and invoices are modeled as structured plain-text and standardized formats in \texttt{data/inbox/}.
  \item \textbf{Justification:} Adding Tesseract or PDF parsing would introduce significant incidental complexity (binary C++ dependencies, noisy extraction artifacts, document layout heuristic failures) that obscures the core evaluation objective: \textbf{autonomous reasoning, tool selection, fault recovery, and deterministic verification}.
\end{itemize}

\subsubsection{4. Omission of SQLite}
\begin{itemize}[leftmargin=*]
  \item \textbf{Decision:} Replaced with in-memory enterprise storage in the mock ERP and production MongoDB structures.
  \item \textbf{Justification:} SQLite lacks native real-time Change Streams, distributed lock support, and horizontal scaling capabilities. MongoDB and Redis mirror the high-throughput, horizontally partitionable datastores utilized in enterprise production.
\end{itemize}
