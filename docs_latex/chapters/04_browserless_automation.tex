\section{Protocol-Level Web Interaction \& Least-Privilege Security}
\label{sec:browserless_automation}

\subsection{Operating Enterprise Systems at the Protocol Layer}
A critical requirement in the Founding Engineer problem statement is building agents capable of operating browsers and internal enterprise portals. While prevailing industry approaches default to heavy headless browser binaries (e.g., Playwright, Puppeteer, Selenium), CentraOperator demonstrates a more resilient, high-performance, and deterministic approach: **protocol-level web automation** executed via Python's standard library (\texttt{urllib.request}, \texttt{http.cookiejar}, \texttt{html.parser}).

Rather than launching a browser instance with thousands of megabytes of resident memory overhead, CentraOperator treats web portals as stateful HTTP protocol endpoints:
\begin{enumerate}
  \item It maintains persistent HTTP session state via an in-memory \texttt{http.cookiejar.CookieJar}.
  \item It parses server-rendered HTML into an \textbf{accessibility-tree-style compact page model}.
  \item It automatically detects, extracts, and transmits hidden CSRF protection tokens.
  \item It executes mutations by encoding and submitting standard \texttt{application/x-www-form-urlencoded} payloads.
\end{enumerate}

\subsection{The PageHTMLParser and Compact Semantic Model}
When raw HTML is returned from the enterprise portal, piping thousands of lines of markup (containing \texttt{<div>} wrappers, CSS classes, and inline styles) into an LLM context window is disastrous: it inflates latency, dilutes attention, and exhausts token budgets.

CentraOperator implements a custom, streaming \texttt{PageHTMLParser} that condenses raw HTML into an actionable semantic dictionary:

\begin{lstlisting}[language=Python, caption={Compact Semantic Page Model Generator (\texttt{services/runtime/tools/web.py})}]
class PageHTMLParser(HTMLParser):
    """
    Condenses raw enterprise HTML into a structured accessibility-style model:
    - Title, Headings (H1-H3)
    - Alerts & Error Banners (alert, alert-error, alert-success)
    - Forms: id, action, method, input fields (id, name, type, value, required, label)
    - Tables: headers, structured row data
    - Action Links: id, text, href
    """
    def to_model(self) -> Dict[str, Any]:
        return {
            "title": self.title.strip(),
            "headings": self.headings,
            "alerts": self.alerts,
            "forms": self.forms,
            "tables": self.tables,
            "links": self.links
        }
\end{lstlisting}

\subsection{Clean Tool Abstractions}
The state graph interacts with web portals strictly through three standardized, idempotent tool primitives registered in the \texttt{ToolRegistry}:

\begin{itemize}[leftmargin=*]
  \item \texttt{web\_open(path: str)}: Sends a \texttt{GET} request to the designated route, tracks cookies, passes the HTML through \texttt{PageHTMLParser}, and returns the compact page model.
  \item \texttt{web\_follow(link\_id: str)}: Resolves an actionable link ID discovered in the page model, retrieves its target URI, and navigates with cookie persistence.
  \item \texttt{web\_submit(form\_id: str, fields: Dict[str, Any])}: Locates the target form in the current page model, populates required inputs, injects hidden tokens (e.g., \texttt{\_csrf}), serializes form parameters, executes a \texttt{POST} request, and captures the resulting redirect or response.
\end{itemize}

\begin{insightbox}[Architectural Future-Proofing: Browser Driver Slot-In]
Because the tool schema is strictly partitioned into \texttt{web\_open}, \texttt{web\_follow}, and \texttt{web\_submit}, \textbf{the underlying implementation can be hot-swapped for a Playwright or Puppeteer headless driver without modifying a single line of state graph logic}. The graph reasons exclusively over high-level tool intentions, preserving total portability across protocol-level and browser-level drivers.
\end{insightbox}

\subsection{Least-Privilege Credential Boundary}
A critical vulnerability in naive agentic implementations is injecting raw database passwords, API tokens, or session secrets directly into the LLM system prompt. This exposes the enterprise to prompt injection attacks, context window leakage, and unauthorized credential exfiltration.

CentraOperator implements a **strict least-privilege security boundary**:

\begin{guardrailbox}[Least-Privilege Security Guarantee]
\textbf{The LLM is completely isolated from enterprise credentials.} The model reasons exclusively with symbolic references, emitting:
\begin{center}
\texttt{\{"tool": "web\_submit", "credential\_ref": "erp\_ap\_clerk"\}}
\end{center}
The \texttt{ToolRegistry} intercepts this symbolic reference and injects the actual credential secrets from an isolated, protected credential store during HTTP request construction. Raw passwords never enter prompt context tokens, checkpoint logs, or client-side telemetry streams.
\end{guardrailbox}
