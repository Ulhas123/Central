\section{Empirical Evaluation Benchmarks \& Stress-Testing}
\label{sec:benchmarks}

\subsection{The Automated Evaluation Suite}
To provide empirical proof of autonomy, reliability, and verification, CentraOperator includes an automated evaluation harness (\texttt{eval/run\_eval.py}) testing a standardized 5-task benchmark suite against environmental faults:

\begin{enumerate}[leftmargin=*]
  \item \textbf{Task 1: Standard Accounts Payable Happy-Path (\texttt{task\_1\_happy\_path})}
  \begin{itemize}
    \item \textit{Prompt:} ``Process the latest Acme invoice from the inbox and match it to its PO in CentraERP.''
    \item \textit{Conditions:} Pristine environment. Invoice amount: $\$1,200.00$ (below $\$5,000$ limit).
    \item \textit{Objective:} Validate end-to-end execution across HTML forms, cookie jar management, CSRF injection, and independent read-path verification without human intervention.
  \end{itemize}

  \item \textbf{Task 2: Policy Threshold Trigger \& HITL Resumption (\texttt{task\_2\_hitl\_limit})}
  \begin{itemize}
    \item \textit{Prompt:} ``Process the latest Apex Global invoice from the inbox and post it into CentraERP.''
    \item \textit{Conditions:} Invoice amount: $\$14,500.00$ (exceeds $\$5,000$ policy limit).
    \item \textit{Objective:} Validate that the deterministic \texttt{gate\_node} halts execution, yields a checkpoint, generates an Approval Card, and smoothly resumes execution upon receiving simulated managerial sign-off.
  \end{itemize}

  \item \textbf{Task 3: Dynamic Fault Recovery under Session Expiry (\texttt{task\_3\_fault\_recovery})}
  \begin{itemize}
    \item \textit{Prompt:} ``Process the Acme invoice under an unstable enterprise session.''
    \item \textit{Conditions:} Target system forcibly invalidates session cookie midway through transaction, redirecting to \texttt{/login?error=session\_expired}.
    \item \textit{Objective:} Validate that \texttt{observe\_node} flags the anomaly, \texttt{adapt\_node} re-authenticates with injected credentials, restores the session, and successfully completes the original operation without operator assistance.
  \end{itemize}

  \item \textbf{Task 4: Silent Failure Detection / Lying UI Defence (\texttt{task\_4\_lying\_ui\_caught})}
  \begin{itemize}
    \item \textit{Prompt:} ``Process the Acme invoice against a deceptive target application.''
    \item \textit{Conditions:} CentraERP renders a green confirmation banner (\textit{``Success: Invoice Recorded''}), but silently drops the transaction in the database engine.
    \item \textit{Objective:} Prove that the agent refuses to trust UI banners. The independent read-path verifier must query the raw database API, discover 0 records in the General Ledger, catch the false-positive, and refuse to issue a completion receipt.
  \end{itemize}

  \item \textbf{Task 5: Zero-Code Workflow Generalization (\texttt{task\_5\_generalization})}
  \begin{itemize}
    \item \textit{Prompt:} ``Review vendor ledger aging for Helios Systems and flag overdue invoices.''
    \item \textit{Conditions:} Entirely different operational workflow (vendor aging review vs AP entry).
    \item \textit{Objective:} Prove that the runtime is domain-agnostic. The identical runtime executes the new task using \texttt{sop\_aging\_review.json} without modifying a single line of Python code.
  \end{itemize}
\end{enumerate}
